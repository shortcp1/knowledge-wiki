# Build vs. Buy Enterprise AI

Tracks decision frameworks and real-world outcomes for enterprises choosing between building proprietary AI capabilities vs. buying point solutions vs. using foundation mod

## Strategic Moat Evolution: SaaS to Agentic (Ball, June 2026)

### Framework Update
**Business Problem**: Understanding where defensibility lives in AI/agentic systems vs traditional SaaS to inform build vs buy decisions

**Key Finding**: Moat location shifts from data layer to orchestration layer

### SaaS Era Moat Mechanics
**Conventional Wisdom (Incorrect)**: Moat = owning system of record = controlling data

**Actual Moat Source**: Workflows touching the system of record
- Hundreds of workflows grabbing data and getting work done
- Some workflows originated from system of record itself
- Others originated elsewhere with one step touching the system
- Platform with most workflow touchpoints = winner

**Why Systems of Record Were Hard to Replace**:
- NOT because of data gravity alone
- The real barrier: reconstructing entire workflow ecosystem
- Required rebuilding/verifying/testing/securing all workflows
- Many workflows were critical path or customer-facing
- Change management cost >> value of switching

### Agentic Era Moat Mechanics
**The Fundamental Shift**:
- **SaaS**: Moat at data layer, workflows formed around it
- **Agentic**: Moat at orchestration layer, workflows become dynamic
- Data layer becomes less important than coordination layer

**New Moat Definition**:
- Not derivative of where data sits
- Lives where work gets orchestrated
- The workflows themselves become the "database"
- Owner of orchestration platform = owner of moat

### Build Strategy Implications
**Common Mistake**: Trying to build orchestration layer from day 1

**Recommended Approach** - The Wedge Strategy:

1. **Start with Single Workflow**:
   - Pick something narrow/niche
   - Choose workflow appearing commoditized (others underestimate it)
   - Select area becoming more important (right wave)
   - Execute much better than anyone else
   - Accept perception of "no defensibility"

2. **Expand from Strategic Real Estate**:
   - Build adjacent workflows around initial wedge
   - Go deeper in certain areas
   - Use initial position as foundation

3. **Build Orchestration Last**:
   - Gradually layer orchestration across workflow portfolio
   - Earn the right to manage/route/govern agents
   - End state: orchestration platform managing agent ecosystem

**Key Principle**: "Startups aren't static" - initial product isn't end state

### Historical Parallel
**Salesforce Example**:
- Didn't start as platform with thousands of workflows
- Started narrow/niche with single use case
- Got really good at that one thing
- Slowly expanded until workflows built around them
- Became system of record through expansion, not by starting there

### Buy vs Build Decision Framework
**For Enterprises**:
- Evaluate vendors on orchestration potential, not just workflow automation
- Look for platforms positioned as strategic real estate
- Consider which workflows are truly differentiating vs commoditizing
- Assess vendor's trajectory toward orchestration layer

**For Vendors/Startups**:
- Don't build orchestration infrastructure prematurely
- Focus on doing one workflow exceptionally well
- Choose starting point with expansion potential
- Plan orchestration layer as evolution, not starting point

### Cross-Reference to Clearinghouse Pattern
The orchestration moat concept aligns with the Clearinghouse pattern:
- Both emphasize coordination/governance over execution
- Both position moat at layer above where work happens
- Both suggest starting narrow and expanding to coordination role
- Orchestration layer IS the clearinghouse for agent workflows

### Generalizability
**Universal Application Across**:
- Any enterprise function with interconnected workflows
- B2B software transitioning from SaaS to agentic models
- Vertical solutions in regulated industries
- Horizontal platforms coordinating multiple departments
- Multi-vendor agent ecosystems requiring coordination

**Industry Examples**:
- Finance: orchestrating payment, compliance, reporting agents
- Healthcare: coordinating care delivery, billing, clinical workflows
- Supply chain: managing procurement, logistics, inventory agents
- Sales/Marketing: orchestrating lead gen, nurture, conversion workflows

### Key Takeaway
The moat in AI-native companies isn't the AI itself, nor the data - it's owning the orchestration layer where dynamic workflows get managed. Build strategy should start narrow, establish strategic position, then expand to orchestration rather than attempting to build orchestration from day 1.
